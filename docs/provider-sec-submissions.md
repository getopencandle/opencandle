# Optional SEC public filings capability

`fetchSecSubmissions({requestId,cik})` fetches only `https://data.sec.gov/submissions/CIK##########.json`. The positive CIK and request ID are the only renderer inputs. The company-facts and submissions methods share one main-process manager: one active request, one-second start spacing, ten-second/32 MiB bounds, fixed declared User-Agent, denied redirects/cookies/auth/retries, upstream denial backoff and `cancelSecRequest`. There is no automatic fetch at startup and no renderer network permission.

The response is `{schemaVersion:1,cik,entityName,data,recentCount,historyFiles,historyFetched:false,provenance}`. Raw data retains reported company metadata and filing columns. Required recent columns are `accessionNumber`, `filingDate`, `form`, `primaryDocument`, all string arrays. Every present column must have that same length and contain only string/number/boolean/null values. Optional and unknown columns remain present exactly as supplied; missing optional columns are not filled. Acceptance date/time is a reported field, not proof of when the information became available to a user or replay process. Filing/report dates, acceptance timestamps and retrieval time remain distinct.

`historyFiles` lists reported older-file names/counts/date ranges. Only matching CIK submissions JSON names are accepted. These are display metadata; no history-file fetch, pagination, filing-document fetch or external execution is exposed. Even an empty history list does not certify complete filing discovery. Coverage is explicitly recent filings, not a general news feed, economic calendar or complete company history. Untrusted titles/descriptions/document names must be rendered as plain text; no HTML is loaded or shell link opened.

SEC's official API documentation establishes public keyless submissions access, compact recent filing arrays and older-history file references. Its public-content reuse and fair-access rules are the same as the company-facts capability. Source field names/types are verified independently against actual public response metadata after synthetic contract tests; those tests are not live provider passes. Actual packaged/UI interaction remains blocked under the existing host restriction.

Tests cover fixed URL/history non-fetching, column alignment/identity/history/input rejection, and shared company-facts active/rate/cancel limits. Existing SEC tests exercise common transport denial/byte bounds/timeout/midstream cancellation. Common `importData({kind:'fundamentals'|'calendar'|'news'})` uses a native JSON-only dialog, existing 64 MiB streamed UTF-8 bound, basename-only return and no renderer destination path. JSON schema/normalization belongs to the selected renderer model; malformed data remains an explicit failure. No native dialog test has passed.

Primary sources: [SEC public APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces), [fair access](https://www.sec.gov/about/developer-resources), [declared-agent/reuse FAQ](https://www.sec.gov/about/webmaster-frequently-asked-questions). No EDGAR filer/account API is used.
