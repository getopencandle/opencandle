# Optional SEC company-facts capability

`fetchSecCompanyFacts({requestId,cik})` is an explicit local desktop action. It issues one GET to `https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json` with a positive user-supplied CIK, padded to ten digits. It does not acquire credentials or connect to EDGAR filer/account APIs. Ticker symbols are mapped to CIKs separately (see the ticker file below), never by this call. `cancelSecRequest({requestId})` cancels this capability; script cancellation remains a separate method.

SEC documents the public `data.sec.gov` APIs as requiring no authentication or API keys. Its FAQ permits reuse of government-created and public filing content. Automated access requires a declared User-Agent and restrained request rate. OpenCandle declares `OpenCandle/0.8.2 (getopencandle.com; optional public SEC data reader)` on data.sec.gov, without inventing a person or contact address. SEC may still deny a request; OpenCandle reports that failure without a workaround. This declared identity is not proof that SEC accepts every request. Its example agent includes a contact address; no personal address is collected or automatically sent by OpenCandle.

Requests allow no redirects, renderer URLs/hosts/headers, cookies, authentication, referrer, persistent cookie jar, automatic retries or external shell links. Only one SEC request is active at a time, start spacing is at least one second, and upstream 403/429 responses suppress new requests for ten minutes (queued and new requests then fail with a resume time). This is stricter than SEC's documented ten-requests-per-second ceiling but cannot control unrelated programs sharing an IP address. The request is capped at ten seconds and 32 MiB of streamed decoded bytes; Content-Length is only an additional early check. Wrong origin/type/status, invalid UTF-8/JSON, unsafe JSON, mismatched CIK or malformed known schema produces a bounded structured error. Cancellation/timeout resolves once, aborts transport and prevents later data delivery. No request occurs at app startup. Renderer networking remains denied.

The success envelope contains `{schemaVersion:1,cik,entityName,data,provenance}`. `data` retains the full accepted raw company-facts object, including taxonomy, concept, units, observations, period dates, values, form, accession, filing date, optional fiscal/frame metadata and unknown fields. Nullable/missing descriptive label metadata remains null/absent; it is not replaced with invented source labels. `provenance` states provider `SEC EDGAR`, kind `public-unauthenticated`, exact source URL, retrieval timestamp, body SHA-256, bytes and limited coverage. It contains no quote freshness assertion, as-known-at-time reconstruction or financial metric normalization. The adapter itself stores nothing; the cache described below does.

SEC aggregates non-custom, entity-wide XBRL concepts. It does not supply every custom/disaggregated filing fact, a market-price feed or a complete fundamental-ratio catalog. Normalization must select taxonomy/tag/unit/period/form/accession/filing date explicitly and preserve restatements. No automatic annualization, YTD subtraction, missing-quarter substitution or latest-restatement backfill is certified by this capability. SEC may correct or remove prior filings; retrieval time and filed date are distinct evidence.

## Ticker file, queue and cache

The same adapter also reads one fixed file, `https://www.sec.gov/files/company_tickers.json` (rows of `{cik_str,ticker,title}`, at most 100,000, 20 second timeout, same no-redirect, JSON-only, 32 MiB rules). It declares `OpenCandle/<version> (getopencandle.com; <contact>)`, where `<contact>` is the single main-process constant `SEC_CONTACT`. While `SEC_CONTACT` is the placeholder `UNSET`, only this ticker fetch is off: it answers `CONTACT_UNSET` without any network call, and users link symbols by importing the file in Fundamentals. No personal address is ever used. A mailbox the project controls must be set before release.

All SEC requests (company facts, submissions, tickers, and the Fundamentals dialog) go through one queue in `electron/sec-cache.cjs`: first in, first out, at most 16 waiting, starts at least one second apart, and requests for the same kind and CIK share one result. Requests are refused with `SEC_DISABLED_RUN` in demo (synthetic Alpaca) and automated or harness runs.

Cached records are written to `<profile>/sec-cache/<sha256 of kind:cik>.json` as `{schemaVersion:1,kind,cik,retrievedAt,sha256,bytes,envelope}`, atomically (temporary file then rename). A record is revalidated on every read and a bad one is deleted and treated as missing. The folder is capped at 256 MB (least recently used first), and a workspace reset deletes it. `loadSecData({requestId,kind,cik,refresh})` takes one of three modes: `cache-only` (never touches the network), `if-stale` (fetches when nothing is cached, when the record was retrieved before today's New York date, or, for the ticker file, more than 7 days ago) and `force` (at most once a minute per CIK, otherwise answered from cache). A failed refresh returns the cached copy together with the error. `openSecFiling({cik,accession})` opens one filing's index page on sec.gov in the browser (main window only).

**Network rule.** No SEC request is sent at startup. Restored charts and the spreadsheet export read the cache only, and symbols with no company (crypto, forex, futures, options, bonds, commodities, indexes, demo charts) send nothing. The first request happens only when the user adds a fundamentals indicator or chooses Refresh company data. After that, at most one refresh of company facts plus submissions per CIK per New York day, and only while a chart carrying the indicator is on screen. The ticker file is fetched at most once per 7 days. The setting Refresh SEC company data daily (Settings, Data sources, on by default) turns the daily refresh off.

Seven tests in `tests/security/public-sec.test.ts` use synthetic transport only: fixed-host/header boundary; raw field preservation/provenance; nullable metadata; redirect/origin/status/content/schema rejection; declared and actual byte limits; active/rate/backoff gates; cancel/timeout/no late result, including active-reader cancellation. Separately, bounded actual host-Node reads accepted Apple and GameStop public JSON after nullable metadata repairs. The final GameStop response normalizes to 510 concepts/23,663 observations while preserving unknown `fy`/`fp`. Only response metadata, counts and hashes were retained. This does not prove packaged Electron execution, native controls or reference financial-ratio parity; a provider error is never counted as a pass.
